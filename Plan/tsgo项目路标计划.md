## 三、任务目标清单（11 项）

### 语法解析
| 任务 | 详情 |
|------|------|
| **语法范式** | 完成 ArkTS（含 ArkUI）语法规范 Spec 定义，实现 Schema 驱动的多端语法解析工具生成 |

### 依赖解析
| 任务 | 详情 |
|------|------|
| **模块导入** | 支持鸿蒙 SDK 初始化与全局对象注入；实现 @kit、@ohos 系统模块、Native（so 包）及第三方包的导入解析 |

### 语义检测
| 任务 | 详情 | 覆盖度 |
|------|------|--------|
| **ArkTS 高性能语法检查** | 技术穿刺 9 条 | 9 类 / 总数 113 条 |
| **ArkUI 装饰器及组件语法检查** | 技术穿刺 8 条 | 8 类 / 总数 135 条 |
| **鸿蒙 API 检测** | API 注解检查：@since、@deprecated、@syscap 等 | — |

### 语法转换
| 任务 | 详情 |
|------|------|
| **ArkUI 语法转换** | ArkUI 组件、组件扩展、装饰器、状态管理等语法转换 |
| **导入语句转换** | Ohmurl、TypeOnly、变量展开等语法转换 |

### 工程编排
| 任务 | 详情 |
|------|------|
| **鸿蒙工程编排** | 模块间 SDK 与依赖信息互通，构建模块依赖图，基于依赖图编排编译任务 |

### 编译优化
| 任务 | 详情 |
|------|------|
| **增量编译** | 文件级增量编译：基于 VFS 追踪文件版本及依赖关系，结合 Hash 比对变更，跳过未改动文件 |
| **并行化编译** | 文件并行化编译：通过线程池管理，并行化执行解析及文件检查 |

### 基础能力
| 任务 | 详情 |
|------|------|
| **统一工具类** | 路径转换、文件读取、进程通信等 |

## 四、阶段详细分解

### Phase 1: 核心穿刺与基础能力（8 周：07.02 → 08.28）

**阶段目标**：
1. **核心方案穿刺及评审**（4周内）
   - 进程及线程池调度方案 - 刘源
   - Rollup 必要性评估- 刘源
   - 插件生态兼容方案- 刘源
   - etsbundle仓功能下沉（API级->管道）- 宇晗、叶楠：7.9 完成功能模块梳理；
   - ArkTS Linter + Checker 融合 - yanchen
   - UI 转换及检测分离 - 叶楠

1. **兼容性保障 - 测试用例建设**（4周）
   - 测试框架设计 - 宇晗（创建一个SR跟踪框架，一个SR跟踪用例）
   - E2E 工程用例 - 文鹏（新增个人私仓，构建端到端测试用例）
   - UT 语法 Spec 用例（300条）- 叶楠
   - Linter检测相关用例（300条+）- yanchen

3. **TS-GO 基础能力建设**
   - 基础语法解析
   - ArkTS 语法树解析
   - 相关单元测试用例建设

**交付物**：
- 方案评审报告
- 测试用例集
- 基础语法解析器 + UT

---

### Phase 2: 单模块编译打通（8 周：08.28 → 10.23）

**阶段目标**：
1. **单 Hap 编译**
   - 单模块 ArkTS 工程编译
   - HelloWorld 示例工程验证

2. **Debug 包生成**
   - 生成 HAP 产物
   - 调试符号支持

3. **基础依赖解析**
   - @kit 系统模块导入
   - 第三方包导入解析

**交付物**：
- 单 Hap 编译能力
- HelloWorld debug 包
- 基础依赖解析模块

---

### Phase 3: 复杂工程编译（8 周：10.23 → 12.18）

**阶段目标**：
1. **多 Hap 编译**
   - 多模块工程编译
   - 模块间依赖解析

2. **多 HSP 编译**
   - 共享包编译
   - 跨模块依赖图构建

3. **检测生成 HAP 产物**
   - 语法检查集成
   - 产物一致性验证

**交付物**：
- 多 Hap + 多 HSP 编译能力
- 模块依赖图
- 检测结果 + HAP 产物

---

### Phase 4: 性能调优与交付（4 周：12.18 → 01.15）

**阶段目标**：
1. **性能调优**
   - 全量编译性能优化
   - 增量编译性能优化
   - 内存占用优化

2. **TDCP 交付准备**
   - 文档完善
   - 测试报告
   - 交付评审

**交付物**：
- 性能优化报告
- 完整测试报告
- TDCP 交付包

## 五、阶段闸门 (Phase Gate)

| 闸门               | 时间点   | 进入条件       | 退出条件                 | 回退触发         |
| ---------------- | ----- | ---------- | -------------------- | ------------ |
| **Gate P1→P2**   | 08.28 | 方案评审通过     | 基础语法解析完成 + UT 覆盖     | 方案未通过评审      |
| **Gate P2→P3**   | 10.23 | 单 Hap 编译成功 | HelloWorld debug 包生成 | 编译失败或产物不一致   |
| **Gate P3→P4**   | 12.18 | 多模块编译成功    | 复杂工程 HAP 产物生成        | 依赖解析失败或性能退化  |
| **Gate P4→TDCP** | 01.15 | 性能达标       | 交付评审通过               | 性能未达标或阻塞 Bug |

## 六、成功指标 KPI

| 指标 | 基线 (当前) | 目标 (TDCP) | 提升 | 度量方式 |
|------|-----------|------------|------|---------|
| 全量编译时间 | ~16 min | ≤ 5 min | **3.2x** | CI 流水线统计 |
| 增量编译时间 | ~6 min | ≤ 2 min | **3x** | IDE 响应时间 |
| 峰值内存 | 20-30 GB | ≤ 10 GB | **50-67%↓** | 系统监控 |
| ArkTS 语法覆盖 | 0% | 10% | — | 语法检查测试 |
| 产物一致性 | — | 100% | — | 二进制 diff |

## 八、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| ArkTS 语法适配复杂度超预期 | 高 | 高 | Phase 1 先做完整 Gap 分析，按优先级分批适配 |
| 多模块依赖解析困难 | 中 | 高 | 参考 Hvigor 现有依赖图实现，渐进式替换 |
| 性能调优效果不达预期 | 中 | 中 | Phase 4 预留缓冲时间，必要时调整目标 |
| 测试用例覆盖不足 | 中 | 中 | Phase 1 投入测试建设，持续补充 |
