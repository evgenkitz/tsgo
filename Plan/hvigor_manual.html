01 Введение

Что такое hvigor, его роль в экосистеме OpenHarmony и почему он был выбран в качестве системы сборки.

Что такое hvigor?

hvigor — это система сборки, разработанная для OpenHarmony и HarmonyOS. Она использует TypeScript в качестве языка конфигурации и обеспечивает декларативное описание процессов сборки, компиляции и упаковки приложений.

hvigor заменил собой предыдущие подходы к сборке и стал стандартом начиная с OpenHarmony 4.0 Release и API 9 в HarmonyOS. Он интегрирован в IDE DevEco Studio (основанную на IntelliJ IDEA) и также может использоваться из командной строки.

ℹ️
Аналогия с Gradle
hvigor для OpenHarmony — это то же, что Gradle для Android. Оба используют DSL на основе JVM/TypeScript, оба управляют зависимостями, тасками и пайплайнами сборки. Но hvigor спроектирован специально под ArkTS/ArkUI и модульную архитектуру HarmonyOS.

Ключевые особенности

🔷 TypeScript DSL

Конфигурация сборки пишется на TypeScript с полной поддержкой IDE: автодополнение, проверка типов, рефакторинг.

⚡ Инкрементальная сборка

hvigor отслеживает изменения файлов и пересобирает только то, что изменилось, значительно ускоряя процесс.

🧩 Модульная архитектура

Поддержка HAP, HAR, HSP модулей с автоматическим разрешением зависимостей между ними.

🔌 Система плагинов

Расширяемая система плагинов для компиляции ArkTS, упаковки ресурсов, сигнатурного подписания и т.д.

🎭 Конфигурации сборки

Встроенная поддержка Debug/Release режимов, кастомных product'ов и таргетов.

📦 Управление пакетами

Интеграция с ohpm (OpenHarmony Package Manager) для управления внешними зависимостями.

hvigor vs другие системы сборки

✅ Преимущества

  • Нативная поддержка ArkTS/ArkUI
  • TypeScript для конфигурации
  • Глубокая интеграция с DevEco Studio
  • Встроенная поддержка HAP/HAR/HSP
  • Инкрементальная сборка из коробки
  • Автоматическое управление ресурсами (.ets, .png, .json)

⚠️ Ограничения

  • Привязка к экосистеме OpenHarmony
  • Меньше/community плагинов чем у Gradle
  • Документация в основном на китайском
  • Молодая экосистема

Ключевые компоненты

📋 hvigorfile.ts ▼

Основной файл конфигурации для каждого модуля. Определяет, какой плагин использовать и какие таски выполнять. Каждый модуль (entry, feature, library) имеет свой hvigorfile.ts.

На уровне проекта (root) hvigorfile.ts определяет глобальную конфигурацию и таски, применимые ко всем модулям.

📐 build-profile.json5 ▼

Определяет модули проекта, режимы сборки (Debug/Release), target'ы (phone, tablet, wearable и т.д.), и конфигурации signing'а. Это основной файл описания проекта.

📦 oh-package.json5 ▼

Аналог package.json в npm. Определяет имя пакета, версию, зависимости (dependencies, devDependencies), и настройки репозитория для ohpm.

🔌 Плагины (Plugins) ▼

Плагины — это расширения hvigor, которые добавляют конкретные таски. Основные встроенные плагины:

  • @ohos/hvigor-ohos-plugin — основной плагин для OpenHarmony
  • app-plugin — таски для сборки .app файла
  • hap-plugin — таски для сборки HAP модулей
  • har-plugin — таски для сборки HAR библиотек
  • hsp-plugin — таски для сборки HSP shared-модулей
🏗️ ArkCompiler ▼

ArkCompiler — компилятор ArkTS/JavaScript, который транслирует исходный код в байткод для виртуальной машины ArkVM. Вызывается через плагин hap-plugin/har-plugin в процессе сборки.

🔄 hvigor Daemon ▼

hvigor использует демон (фоновый процесс) для ускорения последующих сборок. Демон держит в памяти кэш конфигураций, граф зависимостей и результаты инкрементальной сборки.

Управление демоном: hvigorw --daemon / hvigorw --stop

03 Установка и настройка

Как установить hvigor, настроить окружение и начать работу с системой сборки.

Предварительные требования

  • Node.js ≥ 16.0 (рекомендуется LTS версия)
  • DevEco Studio (рекомендуется, включает hvigor)
  • ohpm — менеджер пакетов OpenHarmony (поставляется с DevEco Studio)
  • Java JDK ≥ 17 (для некоторых плагинов)

Установка через DevEco Studio

Самый простой способ — использовать DevEco Studio, которая поставляется со встроенным hvigor:

Terminal
$ # Проверка версии hvigor
$ ./hvigorw --version
hvigor version: 4.2.1

$ # Проверка версии Node.js
$ node --version
v20.11.0

$ # Проверка версии ohpm
$ ohpm --version
ohpm 2.0.0

Создание нового проекта

При создании проекта через DevEco Studio автоматически генерируется необходимая структура:

Terminal
$ # Создание нового проекта через CLI (если доступно)
$ hvigorw init my-app --template empty
✓ Project created successfully
✓ hvigorfile.ts generated
✓ build-profile.json5 generated
✓ oh-package.json5 generated

$ cd my-app
$ hvigorw assembleHap --mode module -p product=default
✓ BUILD SUCCESSFUL in 12s
⚠️
Wrapper скрипт
Всегда используйте hvigorw (wrapper) вместо глобального hvigor. Wrapper гарантирует, что все разработчики проекта используют одинаковую версию hvigor, указанную в hvigor/hvigor-wrapper.js.

Структура wrapper'а

hvigor/hvigor-config.json5 
{
  "hvigorVersion": "4.2.1",
  "dependencies": {
    "@ohos/hvigor": "4.2.1",
    "@ohos/hvigor-ohos-plugin": "4.2.1"
  },
  "node-version": ">= 16.0.0"
}

05 hvigorfile.ts

Детальное описание конфигурационного файла hvigor — основного файла настройки сборки.

Root-level hvigorfile.ts

Файл на уровне проекта определяет глобальную конфигурацию и подключает плагины:

hvigorfile.ts (root) 
// Импорт ядра hvigor и плагина OpenHarmony
import { appTasks } from '@ohos/hvigor-ohos-plugin';

export default {
    system: appTasks(),  // Подключение системных тасков
    plugins: []          // Кастомные плагины
}

Module-level hvigorfile.ts

Файл на уровне модуля определяет специфичные для модуля таски:

entry/hvigorfile.ts 
import { hapTasks } from '@ohos/hvigor-ohos-plugin';

export default {
    system: hapTasks(),  // HAP-специфичные таски
    plugins: []
}

hvigorfile.ts для HAR библиотеки

library/hvigorfile.ts 
import { harTasks } from '@ohos/hvigor-ohos-plugin';

export default {
    system: harTasks(),  // HAR-специфичные таски
    plugins: []
}

hvigorfile.ts для HSP shared модуля

shared/hvigorfile.ts 
import { hspTasks } from '@ohos/hvigor-ohos-plugin';

export default {
    system: hspTasks(),  // HSP-специфичные таски
    plugins: []
}
ℹ️
Системные таски (system tasks)
Функции appTasks(), hapTasks(), harTasks(), hspTasks() возвращают предустановленные наборы тасков. Они автоматически подключают все необходимые этапы: компиляцию, упаковку, подписывание. Вы можете расширять или модифицировать эти наборы через параметр plugins.

Расширение hvigorfile.ts — кастомные таски

Вы можете добавлять собственные таски и модифицировать существующие:

entry/hvigorfile.ts — с кастомным таском 
import { hapTasks, HvigorTask, HvigorPlugin } from '@ohos/hvigor-ohos-plugin';

// Создание кастомного плагина
const myCustomPlugin: HvigorPlugin = {
    apply(context: HvigorTaskContext) {
        // Регистрация кастомного таска
        context.registerTask({
            name: 'customLogTask',
            execute(taskContext: HvigorTaskContext) {
                console.log('🚀 Выполняется кастомный таск!');
            }
        });
    }
};

export default {
    system: hapTasks(),
    plugins: [myCustomPlugin]
}

Модификация существующих тасков

hook в существующий таск 
const buildHookPlugin: HvigorPlugin = {
    apply(context) {
        // Хук ДО выполнения compileArkTS
        context.beforeTask('compileArkTS', () => {
            console.log('📝 Перед компиляцией ArkTS...');
            // Например, генерация файлов, проверка линтером
        });

        // Хук ПОСЛЕ выполнения packageHap
        context.afterTask('packageHap', () => {
            console.log('✅ HAP файл успешно упакован!');
            // Например, копирование артефакта в другую директорию
        });
    }
};

07 Типы модулей

OpenHarmony поддерживает три основных типа модулей: HAP, HAR и HSP.

Сравнение типов модулей
📱 HAP
Harmony Ability Package
Исполняемый модуль
📚 HAR
Harmony Archive
Статическая библиотека
🔗 HSP
Harmony Shared Package
Динамическая библиотека
Характеристика HAP HAR HSP
Тип Исполняемый Статическая библиотека Динамическая библиотека
Расширение .hap .har .hsp
Может быть entry point ✅ Да ❌ Нет ❌ Нет
Компиляция В байткод .abc В байткод .abc В байткод .abc
Встраивание — Копируется в HAP Линкуется динамически
Общий между HAP — Нет (дублируется) ✅ Да (общий)
Плагин hapTasks() harTasks() hspTasks()
Размер Полный Включается в HAP Отдельный пакет
💡
Когда использовать HSP?
Используйте HSP, когда у вас несколько HAP модулей (например, основной app + feature modules) и вы хотите共享 общие компоненты, ресурсы и код без дублирования. Это уменьшает итоговый размер приложения.

Кастомные таски — полный пример

entry/hvigorfile.ts — расширенный пример 
import { hapTasks, HvigorPlugin, HvigorTaskContext } from '@ohos/hvigor-ohos-plugin';

// Плагин для генерации version info перед сборкой
const versionInfoPlugin: HvigorPlugin = {
    apply(context: HvigorTaskContext) {
        context.registerTask({
            name: 'generateVersionInfo',
            dependencies: ['preBuild'],  // Выполняется после preBuild
            execute(taskContext) {
                const fs = require('fs');
                const path = require('path');

                const version = JSON.parse(
                    fs.readFileSync('oh-package.json5', 'utf8')
                ).version;

                const buildTime = new Date().toISOString();
                const content = `export const VERSION = '${version}';\n` +
                               `export const BUILD_TIME = '${buildTime}';\n`;

                fs.writeFileSync(
                    path.join('src/main/ets/generated', 'VersionInfo.ets'),
                    content
                );
                console.log(`✅ Version info generated: ${version}`);
            }
        });
    }
};

export default {
    system: hapTasks(),
    plugins: [versionInfoPlugin]
}

10 Режимы сборки

Debug vs Release, кастомные конфигурации и управление вариантами сборки.

Debug режим

Используется во время разработки. Включает:

  • Отладочные символы
  • Отсутствие обфускации
  • Быстрая компиляция
  • Debug-сертификат для подписи
Запуск в Debug режиме 
$ ./hvigorw assembleHap --mode module -p product=default -p buildMode=debug

Release режим

Используется для продакшена. Включает:

  • Обфускация кода
  • Оптимизация байт-кода
  • Продакшен-сертификат
  • Удаление отладочной информации
Запуск в Release режиме 
$ ./hvigorw assembleHap --mode module -p product=default -p buildMode=release

Кастомные режимы

Вы можете создавать собственные режимы сборки:

      { "name": "debug" },
      { "name": "release" },
      { "name": "staging" },
      { "name": "enterprise" }
    ]
  }
}

11 Система плагинов

Расширение hvigor через кастомные плагины.

Создание плагина

plugins/MyPlugin.ts — кастомный плагин 
import { HvigorPlugin, HvigorTaskContext, HvigorNode } from '@ohos/hvigor';

interface MyPluginOptions {
  message: string;
  verbose: boolean;
}

export function myPlugin(options: MyPluginOptions): HvigorPlugin {
  return {
    apply(context: HvigorTaskContext) {
      // Получить доступ к конфигурации модуля
      const modulePath = context.module.name;

      // Зарегистрировать таск
      context.registerTask({
        name: 'myPluginTask',
        execute(taskContext) {
          if (options.verbose) {
            console.log(`[${modulePath}] ${options.message}`);
          }

          // Доступ к файловой системе модуля
          const fs = require('fs');
          const files = fs.readdirSync(taskContext.modulePath);
          console.log(`Files: ${files.length}`);
        }
      });

      // Хуки к существующим таскам
      context.beforeTask('compileArkTS', () => {
        console.log('🔍 Проверка кода перед компиляцией...');
      });

      context.afterTask('packageHap', () => {
        console.log('📦 Артефакт готов!');
      });
    }
  };
}

Использование плагина

hvigorfile.ts 
import { hapTasks } from '@ohos/hvigor-ohos-plugin';
import { myPlugin } from './plugins/MyPlugin';

export default {
    system: hapTasks(),
    plugins: [
        myPlugin({
            message: 'Hello from my plugin!',
            verbose: true
        })
    ]
}

Типичные ошибки и решения

❌ "Module not found" при сборке ▼

Причина: Зависимость не установлена или путь в oh-package.json5 указан неверно.

Решение:

$ ohpm install
# Проверьте пути в oh-package.json5
# Убедитесь, что целевой модуль существует
❌ "Signing failed" при сборке ▼

Причина: Неверная конфигурация подписи или отсутствующие сертификаты.

Решение: Проверьте build-profile.json5 → signingConfigs. Убедитесь, что пути к сертификатам верны и пароли корректны. Для автоматической подписи используйте autoSign: true в DevEco Studio.

❌ "hvigor daemon crashed" ▼

Причина: Daemon процесс завершился аварийно (часто из-за нехватки памяти).

Решение:

$ # Остановить daemon
$ ./hvigorw --stop
$ # Увеличить память для Node.js
$ export NODE_OPTIONS="--max-old-space-size=4096"
$ # Перезапустить сборку
$ ./hvigorw assembleHap
❌ "Resource compilation failed" ▼

Причина: Ошибка в ресурсах — неверный JSON, отсутствующие файлы, дубликаты ID.

Решение: Проверьте файлы в resources/base/. Убедитесь, что все JSON файлы валидны, нет дубликатов resource ID, и все ссылки на ресурсы корректны.

15 Оптимизация сборки

Техники ускорения сборки и оптимизации конфигурации hvigor.

1. Инкрементальная сборка

hvigor по умолчанию использует инкрементальную сборку. Убедитесь, что она не отключена:

hvigor-config.json5 
{
  "hvigorVersion": "4.2.1",
  "dependencies": { ... },
  "enableIncrementalBuild": true,    // ✅ Включено по умолчанию
  "enableDaemon": true,              // ✅ Daemon для ускорения
  "enableParallelBuild": true       // ✅ Параллельная сборка
}

2. Исключение файлов из компиляции

build-profile.json5 — исключение файлов 
{
  "buildOption": {
    "arkOptions": {
      "excluded": [
        "**/test/**",
        "**/*.test.ets",
        "**/*.mock.ets",
        "**/generated/**"
      ]
    }
  }
}

3. Кэширование

hvigor автоматически кэширует результаты тасков. Кэш хранится в .hvigor/. Для сброса кэша:

$ # Полная очистка кэша
$ ./hvigorw clean
$ rm -rf .hvigor/

$ # Сброс только daemon
$ ./hvigorw --stop

4. Параллельная сборка

При сборке нескольких модулей hvigor может выполнять таски параллельно:

$ ./hvigorw assembleApp --parallel
🔄 Building modules in parallel...
[entry] compileArkTS ...
[library] compileArkTS ...
[shared] compileArkTS ...
✓ BUILD SUCCESSFUL in 8.2s (was 14.1s sequential)

5. Оптимизация ArkTS компиляции

⚡ Советы по ускорению компиляции

  • Исключайте тестовые файлы из arkOptions.excluded
  • Разбивайте большие модули на несколько HAR — hvigor может компилировать их параллельно
  • Используйте HSP вместо HAR для shared кода — компилируется один раз
  • Увеличьте память Node.js: NODE_OPTIONS="--max-old-space-size=4096"
  • Не используйте --force без необходимости — это отключает кэш
  • Держите hvigor и плагины обновлёнными — каждая версия приносит оптимизации

16 Миграция

Переход на hvigor с других систем сборки и миграция между версиями.

С FA (Form Ability) на Stage модель

При переходе с FA-модели на Stage-модель необходимо:

  1. Изменить apiType в build-profile.json5 на "stageMode"
  2. Обновить module.json5 — новая структура манифеста
  3. Мигрировать код с JavaScript/Java на ArkTS
  4. Обновить hvigorfile.ts — использовать hapTasks() вместо старых тасков

Миграция между версиями hvigor

Из → В Что изменить
3.x → 4.x Обновить hvigor-config.json5, обновить плагины, проверить API тасков
FA → Stage Изменить apiType, обновить манифест, мигрировать код
npm → ohpm Заменить package.json на oh-package.json5, использовать ohpm

17 Best Practices

Рекомендации по организации проекта и настройке hvigor.

📁 Модульная архитектура

Разделяйте приложение на небольшие модули (HAR/HSP). Это ускоряет инкрементальную сборку и улучшает переиспользование кода.

🔖 Версионирование

Используйте семантическое версионирование. Фиксируйте версии зависимостей в oh-package.json5 для воспроизводимости сборки.

🚫 .gitignore

Не коммитьте build/, .hvigor/, oh_modules/. Коммитьте только oh-package.json5 и hvigor-config.json5.

🔒 Безопасность

Не храните пароли от keystore в build-profile.json5. Используйте переменные окружения или secure storage DevEco Studio.

🧪 Тестирование сборки

Добавьте CI/CD пайплайн с ./hvigorw assembleHap --force для проверки воспроизводимости сборки.

📏 Размер HAP

Используйте HSP для shared кода между модулями. Исключайте неиспользуемые ресурсы. Включайте обфускацию для Release.

18 FAQ

Часто задаваемые вопросы по hvigor.

Чем hvigor отличается от Gradle? ▼

hvigor использует TypeScript в качестве DSL, тогда как Gradle использует Kotlin/Groovy. hvigor специализирован под OpenHarmony/ArkTS, имеет встроенную поддержку HAP/HAR/HSP модулей и интегрирован с ArkCompiler. Gradle — более универсальная система, используемая в Android, Java и других экосистемах.

Можно ли использовать npm-пакеты в OpenHarmony? ▼

Напрямую — нет. OpenHarmony использует свою систему пакетов — ohpm. Однако существуют совместимые пакеты, опубликованные в ohpm-репозитории. Вы можете обернуть npm-пакет в HAR/HSP модуль, если он не зависит от Node.js API.

Как подключить C/C++ код? ▼

C/C++ код компилируется через buildNative таск, который использует CMake. Создайте директорию cpp/ в модуле с CMakeLists.txt и настройте build-profile.json5 для нативной сборки.

Как настроить CI/CD с hvigor? ▼
# Пример GitHub Actions
# .github/workflows/build.yml

name: Build
on: [push]
jobs:
build:
runs-on: ubuntu-latest
steps:
- uses: actions/checkout@v3
- run: ./hvigorw assembleHap --force
Как уменьшить размер .hap файла? ▼
  • Используйте HSP вместо HAR для shared-кода между модулями
  • Включите обфускацию в release-режиме
  • Исключите неиспользуемые ресурсы через arkOptions.excluded
  • Используйте resource splitting для разных экранов/языков
  • Минимизируйте количество нативных библиотек
